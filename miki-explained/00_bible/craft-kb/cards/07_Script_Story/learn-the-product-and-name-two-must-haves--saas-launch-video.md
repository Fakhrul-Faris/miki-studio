## CREATIVE_INTENT
"You cannot create a video for a software that you do not understand." The director stopped after the kick-off call,
spent time using the product, took more calls and screen recordings, and only then storyboarded. From the first call he
pulled the **two things most important** to the client (his face in the video; showing how the software works) and
built every later decision around them.

## STE_PROCEDURE
1. Before you write line 1, write the episode's two must-haves, one line each.
2. Use the product or process yourself: open the app, walk the counter flow, read the real receipt.
3. Collect a screen recording or photo of every screen the steps will show.
4. Ask the user about any step you cannot do yourself; never guess a screen.
5. Write each step as "tap X → screen Y appears" before writing its voice line.
6. Cut any draft line or shot that serves neither must-have.

## AGENT_EXECUTION
Add a "Must-haves" line under the RECIPE-D §0.1 answers in `episode.md`, plus a "Flow walked" list (screen by screen,
source: own phone / user recording / official help page). Script and shot list cite the flow list, never memory. A
UI-heavy episode (80/20 rule) needs a recording or screenshot for every interface setup before the board.

### Worked example
Topic: "Terima QR di gerai" (S16 how-to, a burger stall in Bangi).
- BEFORE: script drafted from a general idea of DuitNow QR; L05 names menu items from memory, which may not match the
  bank's merchant app at all.
- AFTER: Must-haves: (1) the real QR standee on the stall counter, (2) the exact taps in the merchant app. Flow walked:
  "<screen 1> → <screen 2> → <screen 3>", copied label for label from the user's screen recording (never typed from
  memory). L05 quotes those real button labels, and shot rows 9–11 rebuild those three screens.

### Check
- Are the two must-haves written down before script v1?
- Does every UI step in the script match a screen in a recording or screenshot we hold?
- Did any line or shot survive that serves neither must-have?
