## METADATA
06_Art_Direction | graphic design (poster/landing-page analysis) | frame brief sequencing (Eye/Feeling fields)

## CREATIVE_INTENT
Every effective design walks the viewer through three steps without them noticing: **Attract** (the biggest/boldest
visual element pulls the eye in first), **Intrigue** (a secondary line spikes interest and holds attention), and
**Deliver** (the message/payoff is read last). An Adidas poster example: the shoe + paint splash attracts, the quote
"time to change up" intrigues, and the message below delivers — a visual trap built entirely from hierarchy.

## STE_PROCEDURE
1. Identify the single element in the frame that should attract first — make it the biggest/boldest.
2. Identify the secondary element that should intrigue — give it less visual weight than the attractor but more than the rest.
3. Place the actual message/payoff last in the viewer's scan order, smaller/quieter than the first two.
4. Check the frame reads in exactly that order (attract → intrigue → deliver) before finalizing.

## AGENT_EXECUTION
In the frame brief's Eye field, write the order explicitly as three ranked items tagged attract/intrigue/deliver,
not just a size list. For frame 0 specifically: the hero object + accent = attract; the ≤8-word contradiction text =
intrigue; the number/event that resolves it = deliver.
### Worked example
Topic: frame 0 for "kenapa kedai ni sentiasa penuh waktu tengah hari?" — a busy stall at lunch (illustrative).
BEFORE: hero stall, hook text, and a RM number all land on screen with equal weight — the eye doesn't know where to start.
AFTER: attract = the stall's steaming wok (biggest, accent-lit) → intrigue = the ≤8-word hook text appearing a beat
later, smaller → deliver = the RM number counting up, smallest, landing last on the word it supports.
### Check
- Can you name which single element attracts first, without hesitation?
- Does the intrigue element have less visual weight than the attractor but more than the delivery element?
- Does the actual message/payoff land last in the scan order, not first?
