## CREATIVE_INTENT
Grouped compositions of an odd number of objects (five, not four) read as more visually pleasing than an even
count — even when the layout is otherwise the same. Separately, placing one object larger and centred, flanked by
equal-sized objects on either side, automatically creates a focal point; rearranging the same objects unevenly
diminishes that effect. The two rules compound: an odd-numbered group with one centred, larger hero reads cleanest.

## STE_PROCEDURE
1. When grouping multiple instances of the same object, default to an odd total count (e.g. 5), not an even one (e.g. 4), unless the real count forces otherwise.
2. Within that group, make one instance larger than the rest and place it at the centre.
3. Arrange the remaining instances in equal-sized sets on either side of the centred one (symmetry, not a random scatter).
4. Avoid uneven arrangements (some larger, oddly placed) even with the same object count — the hierarchy weakens.

## AGENT_EXECUTION
For any Style D "multiply with a counter" event (coins, products, customers), default the displayed count to an odd
number where it doesn't contradict the real figure, scale the centre instance up slightly, and mirror the rest
symmetrically either side in the frame brief's Eye field.
### Worked example
Topic: a "5 customers walked past, 1 bought" counter visualisation outside a stall (illustrative numbers, kept real to the claim).
BEFORE: five identical customer icons scattered unevenly across the frame — no clear focal point.
AFTER: the five icons (odd count, matching the real number) are arranged with the one who bought centred and
slightly larger, two smaller icons mirrored on each side — an automatic focal point with no extra colour needed.
### Check
- If the count is a design choice (not a fixed real number), is it odd rather than even?
- Is exactly one instance larger and centred, with the rest in equal-sized mirrored sets?
- Would rearranging the same objects unevenly weaken the focal point (if so, the current layout is the better one)?
