## CREATIVE_INTENT
Rather than placing every prop, piece of clutter, or plant at once, add them in small batches (a few garbage bins
and roadblocks, then re-check; then trees, then re-check) and judge the whole composition again after each pass.
More silhouette-breaking elements generally strengthens the design, but only if each addition is checked against the
camera view before the next batch goes in — including letting elements interact unexpectedly (e.g. trees growing out
of a building) when it serves the silhouette, rather than only placing things "correctly."

## STE_PROCEDURE
1. Add one small batch of secondary props/set-dressing elements at a time (not everything at once).
2. Re-check the full composition through the actual camera view after each batch.
3. Judge whether the added batch strengthened the silhouette/visual interest before adding the next.
4. Allow an element to interact with another in an unplanned way (a plant growing onto a structure) if it improves the silhouette, rather than insisting on strict placement rules.
5. Keep adding batches until the composition reads as rich enough for the camera's frame — stop once further additions stop improving it.

## AGENT_EXECUTION
In the board-check pass for a dressed set, log each set-dressing batch and a one-line verdict ("added: roadblocks +
bins — verdict: stronger ground-level silhouette, keep") before moving to the next batch, instead of dressing the
whole set in one pass and reviewing only the final still.
### Worked example
Topic: dressing a construction-site backdrop behind a hero hand-truck prop (illustrative).
BEFORE: all clutter (bins, barriers, debris) placed in one pass, then the whole frame judged once at the end.
AFTER: barriers placed first and checked (verdict: reads too empty still) → bins added, checked (verdict: ground
level now reads busy) → a single overturned crate added leaning into a barrier, checked (verdict: adds the "messy"
feel the line needs) — each addition evaluated before the next.
### Check
- Was each batch of added elements checked against the camera view before the next batch was added?
- Did each batch have a stated verdict (stronger/weaker/neutral) before moving on?
- Did additions stop once further elements stopped improving the read, rather than overloading the frame?
